# AgentFlow 三场景真实模型对比实验

## 实验设置

- 模型：DeepSeek `deepseek-chat`
- 质量阈值：80 分
- 场景数：3（科研治理简报、可复现数据分析方案、科研诚信与合规）
- 方法：单 Agent、固定串行“规划→写作”、AgentFlow 多 Agent 动态协作
- 评审：三种方法共用同一质量评审 Agent
- 成本控制：多 Agent 对比运行关闭自动返工，避免不同方法因循环次数不同产生失控调用

## 结果

| 场景 | 单 Agent | 固定串行 | 多 Agent |
|---|---:|---:|---:|
| 科研治理简报 | 86 | 82 | **88** |
| 数据分析方案 | **88** | **88** | 78 |
| 科研诚信与合规 | 78 | **82** | 78 |
| 平均质量分 | **84.0** | **84.0** | 81.3 |
| 成功率（≥80） | 66.7% | **100%** | 33.3% |
| 平均 Token | **3,168** | 5,733 | 23,185 |
| 平均耗时 | **13.86 秒** | 20.62 秒 | 63.87 秒 |

## 结论与问题定位

当前样本下，多 Agent 在综合科研治理题上取得最高分，但平均质量和成功率未超过较简单基线，且 Token 与耗时显著更高。因此项目不能宣称“多 Agent 必然优于单 Agent”，更准确的结论是：平台已经实现可审计的协作、并行、核验和返工链路，但调度与证据整合策略仍需优化。

两次 78 分的共性问题是：文献节点把“本地知识库未覆盖”过度推断为“学术研究空白”；报告初稿完成后，事实核验意见需要经过返工环节才会进入修订稿。对比实验为公平和成本控制关闭了返工，因而暴露了初稿链路的质量短板。

已据此收紧文献 Agent 协议：禁止将本地未检出表述为研究空白，并要求逐字保留完整来源 URL。后续应在修复后复测两个失败场景，并分别报告“初稿质量”和“返工后质量”，而不是只展示最优案例。

## 第一次修复复测

加入“事实核验→报告修订→事实复核→正式评分”后，对数据分析方案场景进行一次真实复测。多 Agent 得分由78降为72，Token由25,085增至41,543，耗时由68.26秒增至97.87秒。审计记录确认新增阶段均被执行，但修订稿从2,283字符膨胀至2,512字符，核验与复核输出分别达到4,048和4,357字符，并混入了与统计方法关系较弱的合规资料。

该结果否定了“增加Agent调用就会提高质量”的假设。后续优化转向两点：其一，按照任务类型约束知识证据用途，统计方法任务不得用政策摘要支撑方法选择；其二，为核验和评审设置反馈预算，只保留最多6项影响验收的关键问题，并要求报告通过替换和压缩完成修订，不能不断追加内容。

> 限制：每类场景仅运行一次，结果会受模型随机性影响，只能作为工程试验基线，不能视为统计显著结论。
