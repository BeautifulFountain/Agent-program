# AgentFlow 科研多智能体协作平台项目报告

## 一、项目概述

AgentFlow 面向科研任务中需求不清晰、资料来源分散、协作过程不可追踪、生成结果缺少验证等问题，构建了一套由知识库、专业 Agent 团队、任务工作流、动态调度、质量评审和反馈返工组成的科研多智能体协作平台。用户可以在统一页面中发起研究任务、确认研究需求、选择 Agent、查看执行流程、核验知识证据，并下载 Markdown 或 Word 格式的正式研究报告。

平台采用 React 构建交互界面，FastAPI 提供任务、Agent、知识库和工作流接口，SQLite 保存任务状态与审计记录，DeepSeek 提供真实大模型能力。系统保留每个节点的输入、输出、耗时、Token、工具调用、评审结果和返工记录，实现任务从创建到最终验收的全链路可追踪。

## 二、知识库定义与集成

平台建立了统一的知识资料结构，每份资料包含标题、发布机构、发布日期、原始链接和正文内容，并按段落切分为可检索证据片段。当前知识库覆盖人工智能、机器学习、深度学习、生成式人工智能、计算机视觉、自然语言处理、数据库、软件工程、网络安全、可信人工智能等专业方向。

知识库支持批量上传、资料预览、单条删除、批量删除和关键词检索测试。检索结果会显示命中文献、相关分、证据片段、来源机构和原始链接，避免知识检索过程成为不可解释的黑盒。

平台同时接入 OpenAlex、Crossref 和 arXiv。文献研究 Agent 执行任务时，先检索外部学术资料，再按 DOI 或来源链接去重，将新资料自动收录到本地知识库，随后统一参与本地检索。事实核验 Agent 可以独立重新读取知识库证据，对报告中的事实、引用和来源一致性进行复核。

## 三、Agent 团队定义

平台定义了七类专业 Agent：

1. 需求分析 Agent：澄清研究问题、范围、指标、约束和交付标准；
2. 任务规划 Agent：拆解任务步骤、依赖关系和执行计划；
3. 文献研究 Agent：检索知识库与外部学术资料，整理证据脉络；
4. 数据分析 Agent：设计指标、变量、分析方法和可复现路径；
5. 报告撰写 Agent：整合前序成果，生成结构完整的科研报告；
6. 事实核验 Agent：检查事实、逻辑、引用来源和约束一致性；
7. 质量评审 Agent：按照统一量表输出质量分、关键问题和修改建议。

每个 Agent 均具有独立角色、系统提示词、能力标签、工具配置、模型版本和启用状态。平台支持新增、编辑、启用和删除 Agent；工作流使用中的必要 Agent 会受到依赖保护，避免误删除导致任务无法执行。

## 四、工作流编排

平台采用有向无环图描述任务工作流。默认流程为：

> 需求分析与人工确认 → 任务规划 → 文献研究与数据分析并行执行 → 报告撰写 → 事实核验 → 质量评审 → 必要时自动返工 → 最终人工验收

工作流页面以流程图展示节点、依赖关系、并行分支、验证节点和返工路径。平台既可以查看默认模板，也可以选择历史任务，查看该任务实际采用的 Agent 流程快照。每次任务保存独立的工作流版本，后续修改模板不会破坏历史审计记录。

## 五、动态调度

用户输入研究任务后，系统根据任务关键词、风险类型、交付形式和研究特征推荐 Agent 组合。需求分析、报告撰写和质量评审属于必要节点；文献研究、数据分析、事实核验和任务规划根据任务内容动态加入。

调度过程会显示推荐的 Agent、命中任务特征和推荐理由，用户可以在任务启动前进行调整。系统根据依赖关系自动识别可并行节点，在依赖满足后执行调度，既保证执行顺序，又减少不必要的串行等待。

## 六、自我循环（Self-Loop）

质量评审 Agent 使用统一量表评价报告完整性、逻辑性、可验证性和约束符合度。当评分低于质量阈值时，系统将关键问题和修改建议反馈给报告撰写 Agent，触发自动返工，并再次经过事实核验和质量评审。

系统限制最大返工次数，同时要求返工分数必须高于上一轮；如果新版本没有改善，自动停止继续循环，避免无意义地消耗 Token。所有历史版本和评分均被保留，最终成果从已评审版本中选择最高分版本，而不是机械采用最后一次输出。

## 七、结果验证

平台采用多层验证机制：

- 事实核验 Agent 独立检查报告中的事实、逻辑和证据；
- 质量评审 Agent 输出结构化评分、问题和建议；
- 引用覆盖率统计最终报告实际使用的证据数量；
- 约束满足率检查篇幅、报告结构、用户明确要求和禁止性内容；
- 工具调用审计展示知识检索、外部资料入库和结构化计算记录；
- 执行时间线记录每个 Agent 的状态、轮次、耗时、Token 和输出。

最终报告只保留正式科研内容，不包含 Agent 分工、评审过程、工具调用、自检说明或系统运行记录。用户可以下载 Markdown 文件或具有正式标题、摘要、关键词、正文、结论和参考来源结构的 Word 报告。

## 八、反馈优化与人工验收

需求分析完成后，平台暂停后续执行，由 Agent 提供可直接勾选的研究范围、指标和证据边界选项。用户确认后，意见会写入审计记录并传递给全部后续 Agent；若推荐选项不能覆盖实际需求，用户可以补充自定义意见。

任务完成后进入最终人工验收。用户查看报告后可以确认成果完成，也可以填写修改意见并选择需要参与返工的 Agent。返工完成后重新执行事实核验和质量评审，只有被采用的版本才成为最终成果，从而形成“自动评审—自动返工—人工验收—定向修改”的反馈优化闭环。

## 九、全链路工程化实现

平台将知识检索、Agent 调用、工作流状态、人工确认、质量评审、自动返工、最终验收和报告下载整合在同一系统内。后端接口、数据库状态、前端页面和审计记录保持同步；任务异常会记录失败节点和错误信息，已完成任务可以查看、下载或删除。

项目已经具备前后端独立启动、真实模型接入、外部知识检索、任务状态持久化、自动化测试和正式成果导出的工程基础，能够完整展示科研多智能体系统从任务输入到成果交付的运行过程。

## 十、总结

AgentFlow 完成了知识库定义与集成、Agent 团队定义、工作流编排、动态调度、Self-Loop、结果验证与反馈优化等核心能力。平台的重点不是简单增加模型调用次数，而是通过明确分工、依赖调度、证据追踪、质量门控和人工参与，使科研任务的生成过程更加可控、可验证、可追溯和可交付。
