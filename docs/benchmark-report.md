# AgentFlow 真实模型对比实验报告（第一轮）

## 1. 实验目的

比较单Agent直接生成、固定串行流程和AgentFlow多Agent动态协作在同一科研简报任务上的质量、成本与响应时间。当前为单任务探索性实验（n=1），用于验证实验方法和发现系统瓶颈，不能作为具有统计显著性的最终结论。

## 2. 控制条件

- 模型：DeepSeek `deepseek-chat`
- 质量阈值：80分
- 任务：撰写约1000字的高校科研管理生成式AI应用价值、风险与治理建议简报
- 共同约束：不虚构调查数据，重点覆盖效率、质量、合规与数据安全
- 统一评审：使用同一质量评审Agent与结构化评分协议
- 执行日期：2026年11月16日

## 3. 结果

| 方法 | 质量分 | 是否达标 | Token | 耗时 | 输出字符数 |
|---|---:|---|---:|---:|---:|
| 单Agent | 86 | 是 | 3,332 | 15.09秒 | 1,753 |
| 固定串行（规划→写作） | 82 | 是 | 5,257 | 20.07秒 | 1,407 |
| 多Agent动态协作 | **88** | 是 | 20,523 | 56.01秒 | 1,730 |

多Agent相对单Agent提升2分，但Token约为6.16倍、耗时约为3.71倍；相对固定串行提升6分，Token约为3.90倍、耗时约为2.79倍。

## 4. 初步发现

1. 多Agent在完整性、逻辑交叉检查和审计轨迹方面表现最好，事实核验Agent能够定位到具体章节和表述。
2. 单Agent在范围明确、篇幅较短的任务上具有明显成本和速度优势，本次得分仅比多Agent低2分。
3. 固定串行增加规划步骤后并未必然优于单Agent，说明增加调用次数不等于提高质量。
4. 三种方法均存在来源可验证性不足的问题，证明知识库引用需要进一步贯穿写作与评审，而不能只停留在文献节点。
5. 本轮模型输出具有随机性，后续需要扩展任务类型并进行重复试验。

## 5. 工程决策

平台不应无条件启用完整多Agent流程。后续可根据任务复杂度、风险等级和交付要求选择策略：

- 简短、低风险、范围明确：单Agent快速模式；
- 需要规划但风险有限：固定串行模式；
- 高风险、需要来源核验、过程审计或多人协作：多Agent完整模式。

## 6. 后续实验

至少补充两类任务：数据分析方案设计、科研诚信/合规评估。每类任务对三种方法分别运行，记录质量分、Token、耗时、约束违反次数和引用完整率。最终报告应给出平均值、波动范围和失败案例，而不是只展示最佳结果。
