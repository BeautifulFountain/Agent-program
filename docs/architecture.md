# AgentFlow 技术架构与创新点

## 调度策略

调度器不采用固定串行脚本。每轮从待执行节点中筛选“所有依赖均已完成”的节点，形成就绪集合并并发执行。该机制使文献研究与数据分析能够在规划节点完成后并行启动，同时保持写作节点对两个分支成果的完整依赖。

每次任务保存工作流快照，后续修改工作流不会破坏既有运行的可复现性。节点记录输入、输出、开始时间、耗时、重试次数、循环轮次和错误，支持审计与复盘。

## 验证与反馈闭环

质量评审 Agent 必须输出结构化 JSON，包括总分、维度分、问题和建议。若总分低于工作流阈值，调度器将反馈定向注入报告撰写、事实核验和质量评审节点，而不是重新执行所有前置研究。达到阈值或最大循环次数后停止，避免无限调用。

## 与基础方案的差异

- 相比单 Agent：具有职责隔离、并行执行和交叉验证能力。
- 相比固定流水线：按依赖状态动态形成并行批次，并保存工作流版本快照。
- 相比无验证编排：质量结果直接控制后续路径，形成可观察的 Self-Loop。
- 相比框架默认示例：调度器、事件模型、验证协议和返工策略均为项目自定义实现。

## 人工智能组件作用与局限

- LLM：完成语义分析、规划、整合和评审；局限是可能产生幻觉和格式漂移。
- 本地检索：为 Agent 提供材料上下文；关键词方案轻量但语义召回能力有限。
- 结构化验证：将主观评审转为可执行控制信号；仍需规则校验或人工抽查降低评审偏差。
- Mock 模式：保证演示与测试可复现，但不能代表真实模型质量和延迟。
